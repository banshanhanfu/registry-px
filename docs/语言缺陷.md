# 语言缺陷（PuXian Language Defects）

> 本仓库在编写生态库过程中暴露的 PuXian 语言缺陷/不直观行为登记。
> **约定**：写库时遇到任何语言面问题（编译/解释不一致、原生函数语义不直观、
> 语法限制、文档与实现不符等），一律追加到本文件（新条目编号 = 当前最大 ID + 1），
> 随当次库的 commit 一起提交。修复/官方回应后可标记状态。
>
> 实测基线：PuXian 0.2.0-m184（aarch64，VM 轨默认）
> （2026-09-23：m184 官方 release 明确修复缺陷 200/201/202 = PX-DEF-002/005/014，条目移除；其余登记保持有效）

## 缺陷登记

| ID | 发现库 | 描述 | 影响 | 绕行 | 状态 |
|---|---|---|---|---|---|
| PX-DEF-003 | decimal/cli | **Result 无 `unwrap_err()` 原语**：只有 `is_ok/is_err/unwrap`（`unwrap` 在 Err 上 panic），拿不到错误值 | 错误信息难提取 | `str(Err(...))` 剥壳（各库 `*_err_msg` helper） | 官方速查表已记录，无修复迹象 |
| PX-DEF-006 | workerpool/testkit | **解释器（`px run`）不支持并发原语**（spawn/send/recv/select/chan/mutex）→ 报"interp 不支持通道（Mini 子集排除）" | 含并发库无法用解释器验证（文档化行为，非缺陷，但写库易踩） | 并发库标注"需编译模式"，测试用 `px build` + 产物运行 | 官方文档化（MINI_SUBSET），非 bug |
| PX-DEF-008 | validator | **`type()` 对字符串返回 `"string"` 而非 `"str"`**：`type("")` 返回 `"string"`（速查表未记录 str 的实际类型名；`type(1)` 是 `"int"`、`type([])` 是 `"list"` 等均与直觉一致） | 按 `type(v) == "string"` 判断字符串，勿用 `"str"` | 文档未覆盖，已实测 | 
| PX-DEF-009 | validator | **`regex_match(pattern, s)` 是完整匹配而非搜索**：`regex_match("a@b", "xa@by")` 返回 false（Go regexp.MatchString 语义是搜索） | 跨实现移植正则断言时需注意；需要子串匹配时 pattern 两端不要隐含 `^$` | 文档未明示，已实测 |
| PX-DEF-010 | 写库综合 | **`pbkdf2_sha256` 的 salt 参数按字符串字节处理，不自动 hex 解码**：`pbkdf2_sha256(pw, "aabb…")` 把 32 字符 ASCII 当 32 字节盐（与 Python `hashlib.pbkdf2_hmac` 传入 `bytes.fromhex` 不同）。传 `hex_to_bytes(...)`（bytes）时与标准**完全一致**（实测 64 字节输出逐字节相同） | 与标准互操作必须显式 hex_to_bytes | native 入参双形态（str/bytes）易误读 |
| PX-DEF-012 | tar | **`bytes(n)` 语义是"数字转字符串字节"而非"N 字节空 buffer"**：`bytes(10)` 返回 `"10"` 的 2 字节（bytes_len=2），非 10 字节全 0 | 造空 buffer 的直觉写法完全错误 | 循环 `bytes_concat(b, bytes("\0"))` 拼 N 次（tar_zero_buf） | 文档未明示，已实测 |
| PX-DEF-015 | checksum | **`len()`/`s[i]` 按 rune、`s[a:b]` 切片按字节，双模式一致但语义混用**：`len("你好")`=2、`s[1]` 取到完整 rune "好"，而 `s[0:1]` 取到首字节 228（断开的 UTF-8 片段）。stdlib strings.px 注释称"下标为字节序下标（与切片同轴）"，实测字符串索引与切片不同轴 | 按字符串下标逐字符做字节运算（校验和/二进制 pack）会漏字节，对拍不一致 | 字节遍历一律 `bytes(s)` + `bytes_len`/`bytes_get`；按 rune 处理用 `s[i]` | 文档与实际不一致，待官方明确语义 |
| PX-DEF-016 | base58 | **`sha256` 返回 hex 串且哈希输入为字符串字节；"标准双 SHA-256"不能写 `sha256(sha256(s))`**：后者是对 64 字符 hex 文本再哈希，与 Bitcoin/Python `hashlib.sha256(digest())` 不一致（实测 `hello` 双哈希，直接用 hex 串得到 d7914fe5…，正确原始字节双哈希得到 9595c9df…） | 需要双哈希校验的库（Base58Check、Bitcoin 地址）直接套用会产出错误校验和 | 先 `hex_to_bytes(sha256(s))` 取原始摘要，`bytes_to_str` 还原为字符串，再 `sha256(bytes_to_str(原始摘要))` | native 返回形态（hex str）与字节语义未文档化 |
| PX-DEF-017 | base58 | **`bytes(chr(n))` 对 n>=128 不是"原始字节"而是 UTF-8 编码**：`chr(185)` 是码点 U+00B9，`bytes(chr(185))` 返回 2 字节 c2b9；`hex_to_bytes("b9")` 才得到单字节 b9（`bytes_to_str`/`bytes()` 往返能保留原始字节 0-255，与 `chr` 构造的 rune 语义不同） | 字节拼接库（base58/二进制 pack）用 chr 造任意字节会产生 1→2 字节膨胀，校验和/长度全错 | 逐字节用 `hex_to_bytes(2 位小写 hex)`；整体用 `bytes_to_str(hex_to_bytes(...))` 承载二进制 | 字符串双模型（rune vs 原始字节）易混 |
| PX-DEF-007 | workerpool | **函数值作为 chan 消息元素传参可用，但注意任务 dict 键访问必须 `.has()` 守卫**：对无键 dict 直接 `d["k"]` 抛 `R1008 字典没有键`（而非返回 null/报可捕获错误） | 宽松读键模式（Python `.get` 心智）不可用 | `task.has("stop") and task["stop"]` 式守卫；或先 `d.keys()` 确认 | 官方速查表已有记载（先守卫再读），非 bug |
| PX-DEF-018 | bytes_pack | **`int_to_bytes` 参数不足时解释轨崩溃**：`int_to_bytes(1)`（缺 size）在 `px run` 报晦涩的 `R1003: 索引越界: 1 (len=1)` 而非参数错误（m182 实测） | 排查参数错误困难，且双模式报错不一致 | 调用前自行保证参数数量；`bytes_pack` 不依赖该 native | 解释轨错误路径缺陷 |
| PX-DEF-019 | bytes_pack | **`bytes_to_int` 的 endian 参数在解释轨被忽略**：`bytes_to_int(bytes(0x0102), "little")` 解释轨返回 258（按大端），编译轨返回 513（小端正确） | 小端解包双模式结果不一致 | 不用 endian 参数：默认大端解析 + 先按字节反转，或手动按字节组装 | 双模式不一致（m182 实测） |
| PX-DEF-020 | bytes_pack | **`int_to_bytes` 的 signed=true + 负值在解释轨返回 null**：`int_to_bytes(-5, 2, "big", true)` 解释轨返回 null（编译轨返回 fffb）；正值正常 | 负数补码打包双模式不一致 | 自实现补码（算术右移）打包，不依赖 signed 参数 | 双模式不一致（m182 实测） |
| PX-DEF-021 | xlsx | **`zip_pack`/`zip_unpack` 在解释轨缺失**：`zip_pack` 调用报 `R1001: 未定义变量`，仅编译轨（px build）可用（M182 实测） | zip 相关库（xlsx/docx/pptx 容器）无法解释轨验证 | 该库标注"需编译模式"；纯 parts 构建在解释轨仍可测 | 解释轨 native 覆盖缺口（同 PX-DEF-006 类） |
| PX-DEF-022 | qrcode | **list 切片是浅拷贝（内层元素共享）**：`m[0:len(m)]` 得到新外层数组，但内层 list 元素仍是同一引用；`var b = a` 更是纯引用。需要整块深拷贝必须手写逐元素循环（每库重复实现 `copy_m`/`list_copy` helper），无 `deepcopy` 原语 | 矩阵/嵌套列表复制易串改原值，边界难查 | 手写双层循环深拷贝；或构建期约束"导出函数不改入参" | 文档未明示，已实测 |
| PX-DEF-023 | qrcode | **`Err(...)` 字符串化嵌套冗长**：`str(Err("a: " + str(Err("b"))))` 输出 `Err(a: Err(b))` 双层包裹，日志/错误传播链路难以阅读 | 多层错误传播时排障信息膨胀 | 顶层捕获后只 `str(err)` 一次并人工剥壳；库内部避免 Err 套 Err | 展示形态，非功能缺陷 |
| PX-DEF-024 | qrcode | **解释器循环性能极差**：QR 掩码罚分全矩阵大循环（8 掩码 × O(n²)）`px run` 单码约 36s，`px build` 编译产物 <1s（同源码实测） | 含大循环/多重循环的库无法用解释器做快速迭代验收 | 写库先用 `px build` 编译产物验收；解释器只做小样例冒烟 | 解释器性能，非语义缺陷（同 PX-DEF-006 类） |
| PX-DEF-025 | qrcode/svg | **字符串无 `.find()`/`.index()` 方法（原生方法面仅 split 等）**：`"abc".find("b")` 报 `R1007 类型 string 没有方法 'find'`；子串定位只能靠手写循环或 `import std.strings` 的 `index_of(s, sub)`。stdlib strings.px 注释自述这是语言级缺口（"语言缺「子串定位」原语"，api-server/token-cache 等 5 处各自手搓同一函数） | 写库时想用 Python 心智 `s.find(sub)` 直接报错；重复手写定位函数 | `import std.strings` 用 `index_of`；或库内自备 contains/index_of helper | stdlib 已承认语言级缺口，非文档未明示 |
| PX-DEF-026 | mysql | **无 `sha1` native**（只有 sha256/hmac_sha256/md5）：`sha1(bytes("abc"))` 报 R1001 未定义变量 | MySQL `mysql_native_password` 认证必需 SHA1（与 MySQL 8 `caching_sha2_password` 的 SHA256 不同族） | 库内自实现 SHA1（registry/mysql/sha1.px，纯 .px FIPS 180-4，0~121 字节向量对拍通过） | 语言缺 SHA1 原语（同 PX-DEF-016 的 sha256 形态不同） |
| PX-DEF-027 | pg/mysql | **字符串方法面极窄**：无 `.strip()`/`.has_prefix()`/`.has_suffix()`，仅 `split` 可作方法（实测 R1007 类型 string 没有方法） | 写库时 Python 字符串心智大面积失效；前缀判断需手写 index_of==0 | 自备 `pg_index_of`/`my_index_of` helper（库内聚）；或 `import std.strings` 用函数式 | 同 PX-DEF-025 族（方法面缺口未在速查表列全） |
| PX-DEF-028 | pg/mysql | **C 风格 `for (;;)` 不支持**：报 `E1001 非法字符: ;`；无限循环只能 `while true:` | 从 C/Go 惯例直接写 `for(;;)` 卡语法错误 | 统一 `while true:` + 显式条件退出 | 语法风格设计（文档 QUICKSTART 未提，易踩） |
| PX-DEF-029 | mysql | **`bytes_get` 越界返回 `null` 而非报错/索引异常**：`bytes_get(1字节buf, 5)` 返回 null | 后续 `null < 251` 比较报晦涩的 R1002 无法比较；协议解析越界难以归因 | 解析前手动 `off >= bytes_len(b)` 守卫（mysql.px my_lenenc_int） | 返回语义未文档化（双模式一致，非致命） |
| PX-DEF-030 | pg | **`bytes_to_int` 读 `0xFFFFFFFF` 返回无符号 4294967295（非 -1）**：PG DataRow 的 NULL 列长度 -1 无法用 `== -1` 判断 | 二进制协议负长度判定错误 → NULL 列解析成数据 | 用 `> 2147483647` 判负（pg.px 的 NULL 判断） | 双模式一致但无符号语义未文档化 |

## 写库时发现的其它限制（非缺陷，设计如此）

- 并发语法（spawn/chan/mutex）仅编译模式（见 PX-DEF-006）
- `let` 不可变，`var` 可变；`{}` 从 M129 起是空 dict（此前是 null）
- `join(sep, list)` **分隔符在前**（与 split 相反，易错）
- `time_format(sec, fmt)` 输出 UTC，本地时间用 `now()`
- dict 键限定 str；`d.set(k,v)` 写、`d.has(k)` 查
- `json_parse_opt` 解析外部 JSON（裸 `json_parse` 遇畸形输入会终止进程）
- 模块顶层不写 `let/var` 状态（写库规范）；有状态用显式传参/dict

## 缺陷复现示例


```px
# PX-DEF-015 复现：len/索引按 rune，切片按字节
var s = "你好"
print(len(s))          # 2（rune 数）
print(s[1])            # 好（完整 rune）
print(bytes_get(bytes(s[0:1]), 0))   # 228（首字节，切片按字节）
# 绕行：字节流处理用 bytes(s) + bytes_len/bytes_get
```

```px
# PX-DEF-016 复现：双哈希陷阱
print(sha256(sha256("hello")))   # d7914fe5…（hex 文本再哈希，非标准双哈希）
var r = hex_to_bytes(sha256("hello"))
print(sha256(bytes_to_str(r)))   # 9595c9df…（标准双 SHA-256 前 4 字节）

# PX-DEF-017 复现：chr 不是原始字节
print(bytes_len(bytes(chr(185))))        # 2（期望 1）
print(bytes_to_hex(bytes(chr(185))))     # c2b9（期望 b9）
print(bytes_to_hex(hex_to_bytes("b9")))  # b9（原始单字节）
```


```px
# PX-DEF-018/019/020 复现（m182 双模式对比）
print(int_to_bytes(1))        # 解释轨: R1003 索引越界; 编译轨: R1002 参数错误
print(bytes_to_int(bytes(0x0102), "little"))  # 解释轨: 258; 编译轨: 513
print(int_to_bytes(-5, 2, "big", true))       # 解释轨: null; 编译轨: 0xfffb
```

```px
# PX-DEF-022 复现：list 切片浅拷贝（内层共享）
var m = [[1, 2], [3, 4]]
var cp = m[0:len(m)]
cp[0][0] = 99
print(m)   # [[99,2],[3,4]] —— 内层被改了！需手写深拷贝
```

```px
# PX-DEF-023 复现：Err 嵌套字符串化
print(Err("a: " + str(Err("b"))))   # Err(a: Err(b))
```

```px
# PX-DEF-024 复现：解释器与编译产物速度悬殊（qrcode encode 大矩阵罚分）
# px run  : ≈36s（掩码 8 × 罚分 O(n²)）
# px build产物: <1s（同源码）
```

```px
# PX-DEF-026 复现：无 sha1 native（MySQL mysql_native_password 认证必需）
# 语言只有 sha256 / hmac_sha256 / md5，无 sha1；
# 写 registry/mysql 需在库内自实现 SHA1（纯 .px，FIPS 180-4，tests 对拍通过）
```

```px
# PX-DEF-027 复现：字符串方法面极窄（无 strip/has_prefix，同 PX-DEF-025 族）
var t = "  hi  "
# t.strip()       → R1007 类型 string 没有方法 'strip'
# t.has_prefix()  → R1007 类型 string 没有方法 'has_prefix'
# 写库需自备 index_of/prefix 等 helper（pg.px 的 pg_index_of / mysql.px 的 my_index_of）
```

```px
# PX-DEF-028 复现：C 风格 for(;;) 语法不支持
for (;;) {}
# E1001: 非法字符: ';'
# 无限循环须写 while true:
```

```px
# PX-DEF-029 复现：bytes_get 越界返回 null 且不报错
var b = hex_to_bytes("01")
print(bytes_get(b, 5))  # null（不崩溃，后续比较 null < 251 报 R1002）
```

```px
# PX-DEF-030 复现：bytes_to_int 读 0xFFFFFFFF 返回无符号 4294967295（非 -1）
# 双模式一致但读 wire protocol 的 -1（NULL 长度）不可用 == -1 判断，
# 需用 > 2147483647 判负（pg.px NULL 列判断）
```
